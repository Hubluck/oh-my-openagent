# CLAUDE.md

이 파일은 Claude Code가 이 Obsidian vault에서 일할 때 따라야 하는 업무 규약입니다.

목표는 개인 메모장이 아니라, 여러 AI 에이전트와 사람이 같은 업무 맥락을 공유할 수 있는 안정적인 비즈니스 프로세스를 만드는 것입니다.

---

## 0. Operating Principles (Karpathy-style)

작업 전에 항상 적용합니다.

1. **가정을 드러내라.** 모호하면 멈추고 질문합니다. 해석이 둘 이상이면 둘 다 보여주고 선택하게 합니다. 절대 조용히 추측하지 않습니다.
2. **최소 변경.** 요청된 결과를 만드는 데 필요한 가장 작은 분량의 문서/구조 변경만 합니다. 요청 없는 리팩토링·예쁘게 정리·"혹시 필요할까봐" 항목은 만들지 않습니다.
3. **국소 수정.** 작업 대상이 아닌 wiki 문서·index·log는 건드리지 않습니다. 단, 내가 만든 변경 때문에 끊긴 링크와 누락된 인덱스는 직접 보강합니다.
4. **검증 가능한 성공 기준.** 모든 작업은 끝나면 "어떻게 확인하면 되는지"를 한 줄로 보고합니다. 예: "이 wiki 문서를 열어 보면 결정 근거와 결정권자 두 줄이 있어야 정상."

## 1. Core Operating Rules

1. 작업을 시작하기 전에 `index.md`, `log.md`, 관련 `AI-Sessions/wiki/` 문서를 먼저 확인한다.
2. `AI-Sessions/raw/` 안의 원본 자료는 수정하거나 삭제하지 않는다 (읽기 전용).
3. 가공된 지식, 결정, 에러, 프로젝트 문서는 `AI-Sessions/wiki/` 아래에 저장한다.
4. 세션 인수인계가 필요하면 `AI-Sessions/conversations/`에 저장한다.
5. 중요한 저장/변경 작업 후에는 `index.md`와 `log.md`를 갱신한다.
6. 사용자가 명시적으로 원하지 않는 한 민감정보·토큰·비밀번호·고객 개인정보를 저장하지 않는다.

## 2. Korean / English Hybrid

- **사람이 읽는 가이드라인은 한국어**로 작성합니다 (톤앤매너, 금지 표현, 기획 기준, 리뷰 기준).
- **에이전트가 인식하는 명령어 키워드는 영어로 고정**합니다.

### Command Keywords

| 명령 | 한국어 자연어 트리거 예시 | 동작 |
|---|---|---|
| `save` | "옵시디언에 저장해줘", "이번 작업 내용 저장해줘", "이거 위키에 남겨줘" | 5필터 통과 시 적절한 wiki 카테고리에 문서 생성 + index/log 갱신 |
| `reference` | "옵시디언 참조", "옵시디언 봐줘", "이전 맥락 불러와줘" | index.md → log.md → 관련 wiki 문서를 읽고 현재 작업 맥락을 복원 |
| `ingest` | "raw 정리해줘", "이 자료 가공해줘" | `AI-Sessions/raw/`의 원본을 읽고 `wiki/sources/`에 요약 문서 생성 |
| `query` | "위키에서 X 찾아줘", "X 관련 문서 검색" | vault 전체에서 키워드/주제 검색 후 관련 문서 목록 반환 |
| `lint` | "위키 점검해줘", "규칙 위반 있는지 봐줘" | 구조·링크·5필터·민감정보 위반 점검 |

자연어가 위 트리거와 비슷하면 해당 명령으로 해석합니다. 모호하면 어떤 명령으로 해석할지 한 번 확인합니다.

## 3. Raw / Wiki Separation

`AI-Sessions/raw/`는 **불변 자료 저장소**입니다.

여기에는 기사 원문, 회의 녹취록, 화면 캡처 설명, 외부 자료 원본처럼 나중에 근거로 다시 확인해야 하는 자료를 둡니다.

에이전트는 raw 파일을 수정하지 않습니다. raw 내용을 바탕으로 요약·판단·결정·기획 자료를 만들 때는 반드시 `AI-Sessions/wiki/` 아래에 별도 문서를 만듭니다.

---

## 4. Wiki Categories

- `AI-Sessions/wiki/sources/`: raw 자료를 요약하고 출처 맥락을 정리한 문서
- `AI-Sessions/wiki/concepts/`: 반복해서 쓰는 개념, 용어, 프레임워크
- `AI-Sessions/wiki/decisions/`: 의사결정, 결정 근거, 결정권자, 날짜
- `AI-Sessions/wiki/errors/`: 실패한 접근, 다시 반복하면 안 되는 실수
- `AI-Sessions/wiki/projects/`: 프로젝트별 진행 맥락과 산출물
- `AI-Sessions/wiki/design/`: 디자인 원칙, IA, 화면 설계 가이드
- `AI-Sessions/wiki/dev-tasks/`: 개발 작업 단위, 의존성, 구현 메모

## 5. Save Filter (필수 5조건)

`save`를 실행하기 전, **다섯 가지를 모두 체크**합니다. 하나라도 만족하지 않으면 wiki에 저장하지 않고, 필요 시 `raw/` 또는 `conversations/`에만 남깁니다.

- [ ] **재사용성** — 이 정보가 향후 실무에 반복해서 재사용될 데이터인가?
- [ ] **인수인계성** — 다른 에이전트나 동료가 프로젝트를 이어받기 위해 반드시 읽어야 하는가?
- [ ] **결정 추적성** — 의사결정의 근거와 결정권자를 나중에 추적할 필요가 있는가?
- [ ] **리스크 기록성** — 실패한 방식이라 다시 시도하면 안 되는 리스크 정보인가?
- [ ] **공통 규칙성** — 팀 전체가 맞추어야 하는 공통 규칙이나 디자인 가이드인가?

**저장 보고 형식**: 어느 항목이 통과했는지 ✅/❌로 표시하고, 통과 사유를 한 줄로 적습니다.

> 예시
> - ✅ 재사용성: 향후 모든 랜딩페이지 카피에 동일 톤 적용 예정
> - ❌ 결정 추적성: 결정권자 명시 없음 → wiki/decisions 대신 wiki/concepts에 저장

## 6. Document Format

새 wiki 문서는 가능하면 아래 형식을 따릅니다.

```markdown
---
type: decision | source | concept | error | project | design | dev-task | handoff
date: YYYY-MM-DD
status: draft | active | superseded
owner: optional
source: optional
---

# 제목

## Summary

## Context

## Details

## Links
```

## 7. Completion Rule

작업이 끝나면 다음을 보고합니다.

- 읽은 주요 파일
- 수정하거나 생성한 파일
- 저장 필터 적용 결과 (5체크리스트 통과 표)
- 다음 세션에서 이어갈 때 먼저 볼 문서

## 8. 하지 말 것

- raw 원본 수정·삭제
- 5필터 통과 못 한 일회성 답변을 wiki에 저장
- 민감정보·토큰·비밀번호·개인정보 저장
- 요청 없이 wiki 구조 리팩토링
- "혹시 필요할까봐" 빈 카테고리/플레이스홀더 만들기
- 이미 결정된 사항을 다시 묻기
