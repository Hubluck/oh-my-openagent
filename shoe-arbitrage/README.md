# 👟 신발 아비트리지 보드

포이즌(시장가) × 국내 리테일(소싱가)을 대조해 **사서 팔면 남는 신발**을 찾는 보드.
데이터를 **조사일별 스냅샷으로 쌓고**, 보드에서 날짜를 골라 필터해서 본다.

## 구조 (데이터 · 빌드 · 화면 분리)

```
shoe-arbitrage/
├── board.html      ← ⭐ 이 파일을 열어서 본다 (자동 생성물, 직접 수정 X)
├── template.html   ← 화면(UI)만. 데이터 없음. 디자인 바꿀 때 여기
├── build.py        ← 엑셀 → JSON → board.html 빌드 파이프라인
├── README.md
└── data/
    ├── 2026-07-04.json     ← 조사일별 스냅샷 (계속 쌓임)
    └── raw/2026-07-04.xlsx ← 원본 엑셀 보존 (읽기 전용)
```

- **데이터**는 `data/<조사일>.json`에 정규화되어 누적된다.
- **화면**은 `template.html` 하나. 데이터는 여기 없다.
- `build.py`가 둘을 합쳐 **자체 완결형** `board.html`을 만든다(외부 의존성 0 → 폰에서 바로 열림).

## 데이터 업데이트 — 두 가지 경로 (같은 포맷 공유)

### A. 폰/브라우저에서 바로 추가 (스크립트 불필요)

board.html을 열고 **`＋ 조사일 추가`** → 엑셀(.xlsx) 선택. (PC에선 화면에 드래그&드롭도 됨)
- 브라우저가 엑셀을 직접 읽어 **이 기기에 스냅샷으로 저장**(localStorage). 조사일 드롭다운에 `·기기` 태그로 표시.
- 새로고침해도 유지됨. 외부 서버·라이브러리 없음(브라우저 내장 압축해제 사용).
- ⚠️ 저장은 **그 기기에만** 됨(기기·브라우저 간 자동 동기화 X). 볼트/다른 기기와 공유하려면 아래 B로 넘긴다:
  - 추가한 조사일에서 **`⬇ JSON 내보내기`** → `<조사일>.json` 다운로드 → `data/`에 넣고 커밋(= B와 동일 포맷).

### B. PC에서 볼트로 커밋 (정식 보관)

```bash
# 1) 원본을 data/raw/ 에 조사일 이름으로 넣는다   예: data/raw/2026-07-11.xlsx
# 2) 한 줄 실행 — 새 엑셀 자동 감지 → 스냅샷 저장 → board.html 재생성
python build.py sync
```

> A로 폰에서 만든 `<조사일>.json`을 `data/`에 넣은 경우엔 `python build.py build`만 하면 board.html에 합쳐진다.

`sync`는 `data/raw/`의 엑셀 중 **아직 스냅샷 없는 조사일만** 골라 반영한다(중복 스킵).
개별 처리도 가능:

```bash
python build.py ingest 아무경로/파일.xlsx            # 조사일은 요약시트에서 자동 감지
python build.py ingest 파일.xlsx --date 2026-07-11   # 조사일 직접 지정
python build.py build                                # 화면/디자인만 바꿨을 때 재생성
```

> 파일명이 `YYYY-MM-DD.xlsx`면 그 날짜가 조사일이 된다. 아니면 엑셀 `요약` 시트의
> "생성 YYYY-MM-DD"를 읽어 자동으로 잡는다.

## 보드에서 보는 것

- **KPI 4칸** — 매칭 수 · 마진＋ 건수 · 평균/최고 마진. 스냅샷이 2개 이상이면 **지난 조사일 대비 증감(▲▼)** 표시. 실수령 설정 시 라벨이 "실수령"으로 바뀜.
- **기회 지도** — 가로=수요(거래량), 세로=마진. 오른쪽 위 "꿀 존"이 잘 팔리고 마진 큰 구간. 점을 누르면 상품 표시.
- **기회 목록(카드)** — 맨 위 **품번(강조) + `⧉ 복사`**(포이즌/소싱 검색에 붙여넣기용) → 브랜드·매장 → 상품명 → 소싱가→시장가 → 마진(+%) → 수요 막대.
- **필터** — 상품/브랜드/**품번** 검색, 브랜드 칩, 정렬(추천순/마진/마진율/수요), **조사일 드롭다운(우상단)**.
  - **마진 남는 것만** 토글
  - **품번당 최저가만** 토글 — 같은 품번이 여러 매장에 있으면 가장 싼 소싱(=마진 큰) 1건만
- **실수령 계산** — 수수료(%)·배송비(원) 입력 시 모든 마진이 `시장가×(1−수수료) − 배송 − 소싱`으로 재계산(실수령). 총마진은 취소선으로 함께 표시. 입력은 기기에 저장(`shoeArb.fees.v1`). 비워두면 총마진 그대로.

## 재고 관리 (📦 내 재고 탭)

기회 찾기와 **별도 카테고리(탭)**. 포이즌 흐름 그대로: 국내 구매 → 보유 → 판매완료.

- 기회 카드의 **`🛒 구매`** → 재고에 담김 (구매가=소싱가, 수량 1, 택배비 3,000, 구매일=오늘, 기준시장가 저장).
- 각 항목에서 **구매가·수량·택배비·구매일** 편집. **`보유중/판매완료`** 토글, 판매완료 시 **판매가·판매일** 입력(기본=시장가 → 실제 체결가로 수정).
- 손익은 **포이즌 수수료 + 택배비** 반영: `단위손익 = 판매가 − 수수료 − 구매가 − 택배비`, 보유중은 기준시장가로 **예상 실현이익**, 판매완료는 **확정 손익**.
- 요약: 보유 수량 · 투자금 · 예상 실현이익 · 확정 손익.
- **내보내기**: `⬇ CSV(엑셀)`(한글 BOM 포함, 엑셀에서 바로 열림) / `⬇ JSON`. `판매완료 정리`로 판 항목 정리.
- 저장은 기기 localStorage(`shoeArb.inventory.v1`).

## 요청 보내기 (보드 → 나에게)

데이터가 들어오는 것과 대칭으로, **요청은 보드에서 채워 내보낸다.**

- **상품별**: 카드의 `📌 요청`을 누르면 "내 요청"에 담기고, 카드/패널에서 **메모 한 줄**을 단다(양쪽 동기화).
- **자유 요청**: "내 요청" 패널의 텍스트칸에 상품과 무관한 요청을 줄 단위로 적는다.
- **내보내기**: `📤 요청 내보내기` → `requests-<조사일>.json` 다운로드. 이 파일을 나에게 주면 상품 코드·조사일까지 붙어 있어 추측 없이 바로 반영한다.
- 저장은 기기 localStorage(`shoeArb.requests.v1`). 다른 기기와 공유하려면 위 내보낸 파일을 넘긴다.

내보내는 형식:
```json
{ "kind":"requests", "snapshot":"2026-07-04",
  "generalRequests":["나이키 신상 조사일 추가"],
  "items":[{"code":"1162011FSTP","name":"호카 본디 9…","brand":"호카","site":"무신사",
            "margin":273183,"vol":62,"mpct":54.4,"note":"수수료 반영 실수령 계산"}] }
```

## 정렬 기준 메모

기본값은 원본 엑셀의 "마진 순"이 아니라 **추천순 = 마진 × 수요**.
엑셀 TOP1(호카 로켓 X 3, +38만)은 거래량 0이라 마진만 보면 오판하기 때문.
가중식: `score = margin × (1 + log10(volume + 10))`. → `template.html`의 `score` 함수.

## 지표 정의

| 항목 | 뜻 |
|---|---|
| 소싱가 | 국내 리테일 최저가 |
| 시장가 | 포이즌 거래 기준가 |
| 마진 | 시장가 − 소싱가 (**포이즌 수수료·배송 제외** — 실수령은 이보다 낮음) |
| 수요 | 포이즌 누적 거래량 |
